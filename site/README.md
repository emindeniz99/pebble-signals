# site/ — the zero-install browser gallery

Generated. **Do not hand-edit anything in here** — `tools/build-site.mts`
rewrites `index.html` and every `apps/<name>/` on the next run.

This is CloudPebble tier 2 (`pnpm run preview -- <app>`, `tools/preview.mts` +
`tools/preview/piu-dom.js`) packaged as a static site: the SHIPPED runtime
(`src/embeddedjs/runtime-build/*.js`, import-mapped) running each example in a
browser against DOM-rendering Piu stubs, five examples to a page, with a
gabbro/emery shape toggle. The competitors people actually click are a URL;
this is ours.

## Regenerate

```bash
cd projects/signal-piu
pnpm run build:runtime      # only if runtime-build/ is stale or missing
node tools/build-site.mts   # rewrites site/index.html + site/apps/*
node --test --experimental-vm-modules tests/site.test.mts
```

The generated bytes are **committed on purpose** — Pages serves this directory
as-is, so the checked-in tree IS the deploy artifact. Regenerate after touching
any of the five examples, the runtime, or `tools/preview/piu-dom.js`, and
commit the result with the change that caused it.

`tests/site.test.mts` is the guard: it asserts every page and bundle exists,
that each import map's runtime modules were actually copied, that no page
loads anything off-origin, and that each bundle still contains its example's
markers (a stale or emptied `app.js` serves a 200 and a blank watch).

## Preview it locally

```bash
python3 -m http.server -d site 8080   # from projects/signal-piu
```

Then open <http://localhost:8080/>. **Opening `index.html` over `file://` does
not work** and is not a bug in the site: ES modules and import maps need a real
origin, and `file://` is opaque, so the browser blocks every module load and
you get empty watches. Serve it.

## One-time GitHub Pages setup

**Repo Settings → Pages → Source: "Deploy from a branch" → Branch: `main`,
Folder: `/ (root)` → Save.** The gallery is then at:

```
https://<owner>.github.io/<repo>/projects/signal-piu/site/
```

One correction worth knowing before you go looking for it: GitHub's
branch-deploy folder picker offers **only `/ (root)` and `/docs`** — an
arbitrary subdirectory such as `/projects/signal-piu/site` is *not* a
selectable folder. Serving this directory therefore means one of:

- **Root deploy (above)** — the whole branch is published and this directory
  is reachable at its repo path. Nothing to maintain, one extra path segment
  in the URL. This is the recommended option for a monorepo.
- **A `gh-pages` branch whose root IS this directory** — if you want the bare
  `https://<owner>.github.io/<repo>/` URL:

  ```bash
  git subtree push --prefix projects/signal-piu/site origin gh-pages
  ```

  then point Pages at branch `gh-pages`, folder `/ (root)`. Re-run the subtree
  push after each regeneration.

Branch deploys run the files through Jekyll. Nothing under `site/` begins with
`_` or matches Jekyll's default excludes, so it passes through unchanged today;
a repo-root `.nojekyll` would remove the dependency on that fact entirely, but
that is a repo-level file and the owner's call.

All paths in the generated pages are relative and every asset is committed
alongside — there is no CDN, no build step and no server, so any static host
(Pages, S3, `python3 -m http.server`) serves it identically.

## Honest limits

The same ones the preview builder has always had, restated on the page itself:
layout is APPROXIMATE (Piu's layout engine is not reimplemented — the stubs
only render Contents as DOM nodes); the preview bundles the raw `.tsx`, so the
auto-thunk lowering pass never runs and bare reactive props stay static (these
five examples write thunks); lazy modules (`importNow`), bitmaps, the Canvas
Port and the host clock global are not stubbed. That last one is why the
draw-based `ultraface` and the phone-data `weather` face are absent — measured
2026-07 by loading every generated bundle under a Node DOM shim, they fail with
`node.invalidate is not a function` and `watch is not defined` respectively.
Adding them means growing `tools/preview/piu-dom.js` first, not editing the
`APPS` list.

**QEMU stays the truth.** This tier is instant feedback, not device accuracy:
`pnpm run dev -- --app pulse`.
